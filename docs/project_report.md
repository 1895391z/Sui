# AI 驱动的 Aspen HYSYS 反应器建模系统项目报告

## 1. 项目目标与总体方案

本项目面向 Aspen HYSYS V15，目标是让用户直接用自然语言描述反应过程，由系统识别场景、
选择合适的反应器类型、写入工况、驱动 HYSYS 求解，并以统一的结构化结果返回产物组成、
转化率、热负荷、衡算和收敛状态。系统已覆盖甲烷蒸汽重整、甲苯歧化和水煤浆气化三个考核
场景，分别采用 Equilibrium Reactor、Conversion Reactor 和 Gibbs Reactor。

考虑到 HYSYS COM 对象创建接口对对象名称、版本和上下文高度敏感，最终方案采用“不可变
基准模型 + 运行副本”的工程路径：每个场景保留一个经人工核对的 seed，运行时先校验其
SHA-256，再复制到 `cases/runtime`，随后由适配器验证反应器、物流和反应绑定关系，写入用户
参数并求解。该方案没有把每次执行描述为从空白 case 创建全部对象，但显著提高了远程工作站
上的稳定性、可重复性和可审计性，并保证任何运行都不会覆盖原始模型。

## 2. 技术选型与系统架构

项目采用 Python 3.12、pywin32 和 HYSYS COM API。Python 便于快速探索 COM 接口、构建严格
数据模型和编写自动化测试；pywin32 可以直接调用工作站上已安装的 HYSYS，无需部署额外服务。
自然语言入口使用本地确定性解析规则，不依赖网络：它负责场景分类、单位识别、参数提取、
冲突检查和澄清，随后生成统一 `CaseSpec`。Router 延迟加载对应适配器，适配器完成 HYSYS
执行，normalizer 最终生成统一 `CaseResult` 或 `ComparisonResult`。

```text
自然语言 / JSON / 子命令
          ↓
参数提取、单位换算与严格校验
          ↓
CaseSpec / ComparisonPlan → Router → 场景适配器
          ↓
seed校验与副本 → HYSYS COM求解 → 结果读取与衡算
          ↓
CaseResult / ComparisonResult（stdout JSON）
```

CLI 将唯一结果写入 stdout，将连接过程、阶段标志和警告写入 stderr，并通过退出码区分输入
错误、seed 缺失、HYSYS/适配器错误和结果标准化错误。连接管理器在没有活动实例时按正常方式
启动 HYSYS，轮询 `GetActiveObject("HYSYS.Application")`，结束时只关闭本次创建的进程。
双温度 Methane 计划严格串行执行，每个工况使用独立的 HYSYS 会话，禁止并发。

## 3. 探索过程与关键问题

开发初期首先通过只读 COM 探查确认三个手工基准中的实际对象名称、类型、端口和反应绑定，
再分别实现适配器。直接使用 COM `/Automation` 冷激活时，HYSYS 曾发生 CLR 异常退出；通过
“正常启动可执行文件—等待活动 COM 对象—执行—清理自有进程”解决了该问题。统一 CLI 还曾
遇到 Windows 中文输出编码和 PowerShell 重定向包装 stderr 的问题，分别通过显式 UTF-8 输出
和无 shell 的二进制证据采集器解决。

输入安全方面，解析器支持 MPa 到 bar 换算、CH4:H2O 摩尔比、中文温度表达和水煤浆浓度。
对于原题中的 `80000 Nm3/h`，系统不会将标准气体体积流量静默当作浆料质量流量，而是在启动
HYSYS 前返回退出码2，要求提供 kg/h 或换算基准。所有显式但未被消费的工程参数也会触发
澄清，防止默认值掩盖错误输入。

AI 编程助手参与了需求拆解、COM 探查方案、适配器实现、错误诊断、测试设计、文档和验收矩阵
整理。开发过程坚持“小步授权—只读探查—单次冷启动—参数矩阵—统一接口—最终彩排”的顺序，
并通过 Git 提交保留演进轨迹。

## 4. 验证结果

| 场景 | 反应器与代表工况 | 主要结果 |
|---|---|---|
| 甲苯歧化 | Conversion，10000 kg/h、380°C、25 bar、50% | 转化率50%，苯2119.311 kg/h，总二甲苯2880.689 kg/h，质量误差0 |
| 甲烷重整 | Equilibrium，13.5 bar，710/600°C | CH4转化率54.035%/30.352%，热负荷1080.757/544.851 kW |
| 水煤浆气化 | Gibbs，1000 kg/h、62 wt%、40 bar、1400°C | CO收率40.863%，碳转化率61.294%，质量误差0.002214% |

项目现有68项离线回归测试，覆盖自然语言解析、严格数据模型、Router、结果归一化、连接管理和
seed校验。最终演示彩排严格串行执行了一条预期澄清命令和三个成功案例；所有成功案例均收敛，
质量及 C/H/O 元素衡算误差小于0.1%，seed 哈希不变，且没有残留 HYSYS 进程。每轮均保存原始
stdout、stderr、退出码、命令参数和前后进程/seed元数据。

## 5. 工程边界与结论

当前结果有三项必须透明说明。第一，甲苯模型以 HYSYS 的 p-Xylene 代表总二甲苯，o/m/p
分布因题目未给选择性而采用等比例假设推导，并非三个原生组分的预测。第二，Methane 使用
100 kgmol/h 的可线性放大计算基准，尚未绑定某一具体工厂年处理量。第三，Coal 1400°C 超出
当前组件报告的 Gibbs 数据上限973.15°C；HYSYS 虽数学收敛，但结果标记为
`engineering_validation_status=limited`，不能直接作为经验证的工业设计数据。

综上，本项目已经完成三个固定场景的自然语言输入、反应器选择、HYSYS 联动、求解、结果读取、
安全失败和可审计证据闭环。系统适合作为稳定的考核演示和后续扩展底座；进一步工作可包括从
空白 case 动态创建全部对象、引入经过验证的高温热力学数据，以及扩展到考核外的新反应场景。
